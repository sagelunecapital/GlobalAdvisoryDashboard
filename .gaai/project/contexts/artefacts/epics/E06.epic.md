# Epic E06: Live API Backend

## Purpose

Fund managers need dashboard data that reflects the current market state on every page load — not a snapshot frozen at the last time a script was run manually. This Epic delivers a live API layer deployed on Vercel that the dashboard fetches on every load, replacing the static HTML data injection pattern.

---

## Scope

- Python Serverless Functions deployed in Vercel's `api/` directory
- Five endpoints: `/api/health`, `/api/regime`, `/api/macro`, `/api/liquidity`, `/api/regime-macro`
- Each endpoint fetches live data from FRED, yfinance, and/or EODData on every request (stateless — no SQLite dependency)
- Dashboard HTML updated to call these endpoints and render live data (replacing JS var injection)
- Architecture validation story (E06S01) gates all other delivery — H-1/H-2/H-3 must be verified before endpoint stories proceed
- Historical chart/time-series data continues to be served from pre-computed JSON files (GH Actions daily update — not changed)

---

## Out of Scope

- Authentication or authorization (internal dashboard, no auth layer in this Epic)
- Persistent storage or caching layer (Vercel KV) — identified as fallback if H-2 fails, not in initial scope
- Modifying `update_dashboard.py` or existing GH Actions workflows
- Migrating historical chart data to API-served format
- A separate backend service (Railway/Render) — Vercel stateless is the chosen architecture; revisit only if H-2 fallbacks fail

## Success Metrics

- Every page load of the dashboard fetches live data — no manual script run required
- `/api/regime` returns current regime within 5s of a cold start
- `/api/macro` completes within Vercel function timeout (validated in E06S01)
- Dashboard shows a clear error state when any API endpoint fails — no silent stale data
