# Story E06S03: Implement /api/macro Live Endpoint

## User Story

**As a** fund manager,
**I want** the dashboard's macro indicator panel to show live values fetched from FRED on every page load,
**so that** I see current readings without needing a script to run first.

---

## Context

The macro module covers 32 indicators fetched from FRED (and GDPNow). Sequential fetching would take ~15s — likely exceeding Vercel's Hobby plan timeout. This story uses parallel fetching (ThreadPoolExecutor) as validated in E06S01 (H-2). If H-2 revealed that parallel fetching is insufficient, this story is cancelled and Discovery generates replacement sub-endpoint stories before any Delivery proceeds.

Delivery must create `api/macro_config.py` containing the full 32-indicator list with FRED series IDs, categories, labels, and frequency metadata. The indicator list and categories match those implemented in `update_dashboard.py`. This file is the authoritative runtime reference — not E03S01.story.md (a discovery artefact, not importable at runtime).

Indicators divide into two frequency classes:
- **Weekly** (WoW% applies): yields (T5YIE, DGS2, DGS10), spreads, credit, monetary (SOFR, IORB), most FRED weekly series
- **Monthly** (MoM% applies): CPI, PCE, PPI, ISM Manufacturing, ISM Services, NFP, Unemployment Rate, Retail Sales, and any FRED series with `frequency: monthly` in `api/macro_config.py`

---

## Acceptance Criteria

- [ ] AC1: `GET /api/macro` fetches all 32 macro indicators using `ThreadPoolExecutor` for parallel FRED API calls; indicator list is loaded from `api/macro_config.py` (which Delivery creates, containing FRED series ID, label, category, frequency class for each indicator); `FRED_API_KEY` read from environment
- [ ] AC2: All FRED calls use `observation_start` set to 60 days before today; this provides sufficient history for both WoW% (weekly) and MoM% (monthly) computation without oversized response payloads
- [ ] AC3: Response includes, for each indicator: `{ "id": str, "label": str, "category": str, "value": float|null, "change_pct": float|null, "frequency": "weekly"|"monthly", "error": str|null }`; for weekly indicators, `change_pct` = WoW% (latest vs value 7 calendar days prior, or nearest prior available value); for monthly indicators, `change_pct` = MoM% (latest vs previous month's latest available value); `change_pct` is `null` if insufficient history is available
- [ ] AC4: GDPNow latest estimate included in response as a top-level field `gdpnow_latest`; source priority: (1) `prototypes/gdpnow.json` if it contains a `fetched_at` ISO-8601 field and the parsed `fetched_at` timestamp is less than 48 hours before the current UTC time — use `gdpnow.json["value"]` directly; (2) FRED series `GDPC1` as fallback (latest annual GDP observation)
- [ ] AC5 (H-2 gate): If E06S01's H-2 benchmark returned FAIL (parallel fetch exceeded 8s), this story is **cancelled** (backlog status: `cancelled`); Discovery must generate replacement sub-endpoint stories (e.g., `/api/macro/yields`, `/api/macro/inflation`, `/api/macro/growth`) before Delivery resumes; Delivery must NOT implement the single `/api/macro` endpoint if H-2 failed
- [ ] AC6 (error-handling): Individual indicator fetch failures are isolated — failed series returned as `{ ..., "value": null, "change_pct": null, "error": "<fred error message>" }`; endpoint returns HTTP 200 with partial data for individual failures; returns HTTP 503 with `{ "error": "all_fetches_failed", "detail": str }` only if every fetch fails

## Notes

If H-2 fails (>8s cold-start for 32 parallel FRED calls), the split options are: (a) sub-endpoints by category, (b) Vercel Pro for 60s timeout, (c) Vercel KV cache. Delivery surfaces this in `api/BENCHMARK_RESULTS.md` and marks this story `cancelled`. Human decides the path.

`api/macro_config.py` is a thin data file (list of dicts), not a fetch library. It does not import `update_dashboard.py` or any src/ module. Its purpose is to make the indicator list inspectable and maintainable without modifying `api/macro.py`.

For GDPNow staleness, `prototypes/gdpnow.json` is a static file served by Vercel — its filesystem `mtime` reflects deploy time, not content age. Only the `fetched_at` field embedded in the JSON payload is reliable for staleness detection.
