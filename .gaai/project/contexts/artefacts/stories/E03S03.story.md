# Story E03S03: Detect 2σ Signals and Generate Natural-Language Alert Reasons

## User Story

**As a** fund manager,
**I want** the dashboard to automatically flag macro indicators that have moved more than two standard deviations from their recent baseline and explain why that matters,
**so that** I can immediately identify unusual macro stress or inflection points without manually reviewing each indicator.

---

## Context

A 2σ signal is triggered when the current raw value of an indicator deviates from its 52-week rolling mean by more than 2 standard deviations (z-score ≥ 2 or ≤ −2). When triggered, the system generates a short natural-language explanation contextualizing why the reading is significant — e.g., "10Y Treasury yield is 2.3σ above its 52-week mean, suggesting a notable acceleration in rate pressure." The alert reason is computed and stored alongside the signal flag so the display layer can render it without additional computation.

---

## Acceptance Criteria

- [ ] AC1: Given rolling mean and std dev are available for an indicator (from E03S02), the system computes a z-score for the current observation: z = (current_value − rolling_mean) / rolling_std_dev
- [ ] AC2: Given z-score ≥ 2 or ≤ −2, the system flags the indicator as having an active signal and stores the z-score, signal direction ("above" or "below"), and signal timestamp
- [ ] AC3: Given an active signal, the system generates a natural-language alert reason that includes: (a) the indicator name, (b) the z-score rounded to one decimal, (c) the direction relative to the baseline, and (d) a one-sentence plain-English interpretation of what the reading means contextually — stored as a text field alongside the signal
- [ ] AC4 (signal-detection): Given z-score between −2 and +2 (exclusive), no signal is generated and the indicator is recorded as within-range — false positives are not generated
- [ ] AC5: Given a new refresh run, the signal state for each indicator is recomputed from the latest observation — prior signal records are retained as an append-only log (each record stores: indicator_id, timestamp, z-score, direction, reason_text, and is_current flag); only the record with is_current=true is surfaced to the display
- [ ] AC6: Given a rolling std dev of zero (all values identical for 52 weeks), the indicator is excluded from signal detection for that period and marked as "signal detection unavailable — insufficient variance" with no false alert generated
- [ ] AC7 (error-handling): Given rolling stats are unavailable for one or more indicators, the system skips signal detection for those indicators and surfaces a visible warning — it does not block detection for the remaining indicators
- [ ] AC8 (signal-detection): The natural-language reason is generated deterministically at runtime — identical inputs (same current value, rolling mean, rolling std dev, and indicator ID) always produce the same reason text. The template structure is defined once by Delivery at build time and may vary per indicator category; runtime behavior from a fixed template is deterministic.

---

## Out of Scope

- Sending alerts or push notifications — this story produces signal data and natural-language text for display consumption only
- Multi-indicator composite signals or cross-indicator pattern detection (future capability)
- User-configurable thresholds (threshold is fixed at 2σ)

---

## Dependencies

- E03S02 — rolling mean and standard deviation must be computed before z-score can be derived

---

## Notes

The natural-language reason template should follow a consistent structure such as: "[Indicator Name] is [z-score]σ [above/below] its 52-week average ([current value] vs. mean [mean value]), suggesting [contextual interpretation]." Delivery should define the template and contextual interpretation logic per indicator category at build time. For example: yield spikes → "rate pressure"; currency moves → "dollar strength/weakness"; commodity moves → "supply/demand signal or risk-off shift." Delivery has latitude to tune the language per category — runtime output from a fixed template is deterministic.
