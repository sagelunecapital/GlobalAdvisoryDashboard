# Story E06S01: Set Up Vercel Python API Skeleton and Validate Architecture

## User Story

**As a** fund manager,
**I want** the dashboard's API layer to be deployed and its core technical assumptions validated before any data endpoints are built,
**so that** subsequent delivery stories are not wasted on an architecture that cannot meet its performance constraints on Vercel.

---

## Context

Three unverified hypotheses (H-1, H-2, H-3) underpin the decision to use Vercel Python Serverless Functions. This story creates the API skeleton, deploys a health endpoint, and validates H-1/H-2/H-3 with concrete evidence. All other E06 stories depend on this one. Architecture decisions D-2 (Vercel Python Serverless) and D-3 (stateless, no SQLite) are implemented here for the first time — no database connections, no caching layers, no persistent state in any api/ file.

---

## Acceptance Criteria

- [ ] AC1: `api/` directory created at repo root with a Python 3.11 serverless function in `api/health.py`; the function exports a standard WSGI-compatible handler using Python's `http.server` module or a minimal framework compatible with Vercel's Python runtime (runtime: `python3.11` declared in `vercel.json`); the function is reachable at `GET /api/health`
- [ ] AC2: `api/requirements.txt` contains pinned versions of `yfinance`, `pandas`, and `requests`; no unpinned or wildcard version specifiers
- [ ] AC3: `GET /api/health` returns HTTP 200 with JSON body `{ "status": "ok", "timestamp": "<ISO-8601 UTC>" }`
- [ ] AC4 (error-handling): `GET /api/health` returns HTTP 503 with `{ "status": "error", "missing_env_vars": ["FRED_API_KEY"] }` (or both keys listed) if `FRED_API_KEY` or `EODDATA_API_KEY` is absent from the runtime environment
- [ ] AC5: `vercel.json` updated to declare `runtime: python3.11` for functions in `api/`, and to continue serving the static `prototypes/` output directory; existing static serving of `index.html` and JSON files is verified unbroken after the update
- [ ] AC6 (H-1 validation): A test deployment to Vercel completes without a bundle size error; if Vercel rejects the deployment due to function size, the story fails and Delivery must escalate before any other E06 story proceeds; the outcome (PASS or FAIL with error message) is documented in `api/BENCHMARK_RESULTS.md`
- [ ] AC7 (H-2 validation): A temporary benchmark function `api/_benchmark_fred.py` issues 10 parallel FRED API calls using `ThreadPoolExecutor`; the function is invoked once via Vercel's test URL on a cold start; total wall-clock time is measured and documented in `api/BENCHMARK_RESULTS.md` with the format `H-2: <time>s [PASS|FAIL] (threshold: 8s)`; after documentation, `api/_benchmark_fred.py` is excluded from Vercel routing via a `routes` entry in `vercel.json` so it is not publicly accessible; if result exceeds 8s, Delivery marks E06S01 done and adds a `blocked` note to E06S03 in the backlog before stopping — it does not proceed to implement E06S03 without a human decision on the split strategy
- [ ] AC8 (H-3 validation): The same benchmark function (or a second function `api/_benchmark_regime.py`, similarly route-excluded) measures the wall-clock time of a combined EODData 90-day MMTH historical pull and yfinance 2-year SPX OHLC download on a cold Vercel invocation; result documented in `api/BENCHMARK_RESULTS.md` with format `H-3: <time>s [PASS|FAIL] (threshold: 5s)`; if result exceeds 5s, Delivery marks E06S01 done and adds a `blocked` note to E06S02 before stopping

## Notes

H-2 failure path: if 10 parallel FRED calls exceed 8s, options are (a) split `/api/macro` into sub-endpoints by category, (b) upgrade Vercel plan for 60s timeout, (c) Vercel KV cache. Delivery surfaces the finding in `BENCHMARK_RESULTS.md` and in a backlog `blocked` note on E06S03. Human decides the path before E06S03 resumes.

H-3 failure path: if combined EODData + yfinance fetch exceeds 5s cold, escalate before E06S02 proceeds. Do not implement the regime endpoint until the timeout risk is resolved.

Benchmark functions (`_benchmark_*.py`) are temporary scaffolding. They must be excluded from public routing via vercel.json but may remain in the repo as documented evidence. They are not production endpoints.

The `api/BENCHMARK_RESULTS.md` file is the deliverable artefact for AC6, AC7, and AC8. Its presence and content are the verifiable condition for these ACs.
