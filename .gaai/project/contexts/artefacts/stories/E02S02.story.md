# Story E02S02: Compute and Persist Net Liquidity Series

## User Story

**As a** fund manager,
**I want** the dashboard to automatically compute the net liquidity series from its raw components,
**so that** I can track the true net injection or drain from the Federal Reserve's balance sheet without manually calculating it.

---

## Context

Net Liquidity = WALCL − WDTGAL − WLRRAL. This is a derived series computed from three raw FRED series already stored in E02S01. It must be recomputed and updated each time new raw data is fetched. The computed series must be stored alongside the raw series so that display and YoY% computation can read from it directly.

---

## Acceptance Criteria

- [ ] AC1: Given raw WALCL, WDTGAL, and WLRRAL records are present in the database, the system computes Net Liquidity = WALCL − WDTGAL − WLRRAL for every weekly date where all three components are available and persists the result as a separate named series
- [ ] AC2: Given the computation is run again after a refresh, only new dates (not yet in the net liquidity series) are computed and appended — existing computed values are not overwritten. FRED occasionally issues revisions to historical weekly data; such revisions are not reprocessed after the initial load — this is an accepted known limitation documented in Notes
- [ ] AC3: Given any of the three component series has a missing value for a given date, that date is excluded from the net liquidity series with a logged warning — a partial calculation is not stored
- [ ] AC4 (error-handling): Given the raw component data is empty or corrupted, the system surfaces a visible error and does not produce or persist any net liquidity values
- [ ] AC5 (data-freshness): Each persisted net liquidity record includes the computation timestamp alongside the date and value

---

## Out of Scope

- Computing YoY% or 3MA — handled in E02S03
- Displaying data — handled in E02S04
- Fetching raw data — handled in E02S01

---

## Dependencies

- E02S01 — raw WALCL, WDTGAL, WLRRAL must be persisted before computation can run

---

## Notes

Delivery should store the computed series under a distinct identifier (e.g., `NET_LIQUIDITY`) separate from the raw FRED series so display and computation layers can query it by name. No external API calls are required for this story — all input data comes from the local database. Known limitation: FRED occasionally issues revisions to historical weekly data (WALCL, WDTGAL, WLRRAL); such revisions are not reprocessed after the initial load. For a weekly-frequency liquidity dashboard, FRED historical revisions are rare and typically immaterial — this limitation is accepted by design.
