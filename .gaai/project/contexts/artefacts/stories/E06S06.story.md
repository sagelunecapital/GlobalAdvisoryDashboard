# Story E06S06: Update Dashboard to Consume API Endpoints

## User Story

**As a** fund manager,
**I want** the dashboard to fetch all live data from the API endpoints on every page load,
**so that** I see current market data without any manual data pipeline step.

---

## Context

The current dashboard HTML reads data from JS variables injected between DATA BLOCK markers by `update_dashboard.py`. This story removes that dependency for current-state data: the dashboard JS fetches `/api/regime`, `/api/macro`, `/api/liquidity`, and `/api/regime-macro` on load, renders the results, and shows clear error states if any endpoint fails. Historical chart data (from regime.json, gdpnow.json) continues to be loaded from pre-computed JSON files.

All four API endpoints must be delivered (E06S02–E06S05) before this story can proceed.

---

## Acceptance Criteria

- [ ] AC1: On page load, the dashboard issues parallel `fetch()` calls to `/api/regime`, `/api/macro`, `/api/liquidity`, and `/api/regime-macro`
- [ ] AC2: The DATA BLOCK markers and injected JS vars for regime, macro, liquidity, and regime-macro data are removed from the HTML; the dashboard renders entirely from API responses for current-state data
- [ ] AC3: While API calls are in-flight, each corresponding dashboard section shows a loading indicator (skeleton or spinner); the page does not appear blank or broken during load
- [ ] AC4 (error-handling): If any API endpoint returns a non-200 status or times out, the corresponding dashboard section displays a "data unavailable" state with the endpoint name and error status; no silent blank panels or stale injected data shown
- [ ] AC5: Pre-computed JSON files (`prototypes/regime.json`, `prototypes/gdpnow.json`) continue to be used for historical chart data; these are not replaced by API calls
- [ ] AC6: `report_date` displayed in the dashboard for the regime section is sourced from the `/api/regime` response `report_date` field (last trading session date — DEC-2026-04-18-03); not hardcoded or derived from `Date.now()`
- [ ] AC7: The updated dashboard is deployed to Vercel and manually verified to show live data on a fresh page load (no cached injected data visible)

## Notes

The dashboard HTML currently has a DATA BLOCK structure where `update_dashboard.py` injects JS `const` declarations. After this story, that injection pattern is dead code for current-state data. The `prototypes/` directory and GH Actions remain in place for historical chart data. The vercel.json `outputDirectory: prototypes` continues to serve the static HTML shell; the API functions are served from `api/`.
