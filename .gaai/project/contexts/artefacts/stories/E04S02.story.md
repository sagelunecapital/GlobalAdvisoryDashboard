# Story E04S02: Style Dashboard Prototype with PlayStation-Inspired Design System

## User Story

**As a** fund manager reviewing the dashboard prototype on Vercel,
**I want** the prototype to be visually styled with the PlayStation-inspired design system,
**so that** I can evaluate the final look-and-feel of the dashboard before live data delivery.

---

## Context

The dashboard prototype (`prototypes/dashboard-prototype.html`) is already deployed to Vercel using a generic dark-orange aesthetic. The design system has now been defined in `PS Design.md` (PlayStation-inspired: dark surfaces, PlayStation Blue as the accent, Inter font, signature hover animations). This story applies that design system to the existing prototype — a visual restyle with no functional changes. All three layers of hardcoded color values must be updated: CSS class declarations, JavaScript chart constants, and HTML inline `style=` attributes.

The target file is `prototypes/dashboard-prototype.html`. The `vercel.json` uses `"outputDirectory": "prototypes"` — no rewrites needed.

---

## Acceptance Criteria

- [ ] AC1 (git safety): Before editing the file, a clean git commit of the current state exists on the `staging` branch. This is the recovery path if post-restyle density is unacceptable.

- [ ] AC2 (CSS colors): All hardcoded CSS color values replaced with PS Design.md equivalents. No `#ff8c00` orange, no `#080808` background, no `#0e0e0e` card surface remains in any CSS rule. The PS surface hierarchy is applied: `#101419` base background, `#1c2026` card/panel surface, `#0070cc` PlayStation Blue for interactive chrome.

- [ ] AC3 (font): Google Fonts CDN link for Inter is added to `<head>`. `font-family` throughout is `'Inter', -apple-system, BlinkMacSystemFont, sans-serif`. All display text 22px and above uses `font-weight: 300`. Body text at 18px uses `font-weight: 400`. No element uses weight 300 below 22px.

- [ ] AC4 (button — primary hover signature): Every `.btn.pri` element implements the full PS hover treatment: background transitions to PlayStation Cyan `#1eaedb`, a 2px `#ffffff` border appears, a 2px `#0070cc` outer ring blooms via `box-shadow: 0 0 0 2px #0070cc`, and `transform: scale(1.2)` is applied. The `transition` property covers background, transform, and box-shadow at 180ms ease. Active state: `opacity: 0.6`. This is non-negotiable.

- [ ] AC5 (button — full radius): All primary buttons use `border-radius: 999px` (full pill). No button has `border-radius: 0` or `border-radius: 2px`.

- [ ] AC6 (danger button): `.btn.dan` maps to PS `warning-red: #c81b3a` for text and border color, `error-container: #93000a` as hover background. It does NOT receive the cyan hover treatment.

- [ ] AC7 (tabs): Active tab state uses PlayStation Blue `#0070cc` (not orange). Inactive tab text uses PS `on-surface-variant: #c1c7d4`. Tab border-radius follows PS scale (min 6px).

- [ ] AC8 (JavaScript chart constants): `GRID_COLOR` and `AXIS_COLOR` constants are updated to PS-compatible values (e.g., `GRID_COLOR` → PS `outline-variant: #414752`; `AXIS_COLOR` → PS `on-surface-variant: #c1c7d4`). All series colors passed to `drawChart()`, `drawMulti()`, and `drawDualAxis()` are replaced with colors derivable from `PS Design.md` tokens.

- [ ] AC9 (inline style= attributes): HTML `<div>` legend dot elements at lines 288–291 (and any other inline `style="background:#..."` color attributes) are updated. No legacy color values survive in inline HTML attributes.

- [ ] AC10 (ALL-CAPS removal): All ALL-CAPS text in labels, tab names, section headings, button text, and card headers is converted to title case or sentence case. The PS design rule ("Don't use ALL-CAPS labels or kickers") is fully applied.

- [ ] AC11 (border radius): No element has `border-radius: 0` or `border-radius: 2px` in the chrome layer. All borders follow PS radius scale (6px minimum for buttons and containers; 12px for cards; 24px for feature panels).

- [ ] AC12 (shadows): Shadow values follow PS elevation scale: `rgba(0,0,0,0.06) 0 5px 9px 0` for panels, `rgba(0,0,0,0.08) 0 5px 9px 0` for cards. No shadow at opacity 0.1, 0.2, 0.3, or 0.5.

- [ ] AC13 (semantic color exceptions): Market Regime badges (`.rbadge.yellow`, `.rbadge.green`, `.rbadge.red`) preserve their semantic signal hues (yellow/green/red) as domain exceptions. PS typography, border-radius, and background padding are applied; the signal hue is preserved. Change indicators (`.chg-neg`) map to PS `error: #ffb4ab`; `.chg-neu` maps to PS `on-surface-variant: #c1c7d4`.

- [ ] AC14 (PS audit checklist — Section 9 of PS Design.md): All eight audit points from PS Design.md § 9 ("Iteration Guide") pass:
  - Display weight: every headline ≥22px is Inter weight 300
  - Hover treatment: every `.btn.pri` has cyan fill + scale(1.2) + white border + blue ring
  - Corners: every container and button uses a PS radius value (no 0px)
  - Color sprawl: only PS-defined colors appear in chrome
  - Surface alternation: header (dark) → content panels (surface-container) — no two same-surface panels fight for attention
  - Casing: sentence/title case only — no ALL-CAPS anywhere
  - Shadow weight: opacity lands on 0.06, 0.08, 0.16, or 0.8 only
  - Whitespace: section gaps give each module adequate breathing room

- [ ] AC15 (Vercel deployment): The restyled file deploys correctly to Vercel. The HTML structure is valid (no broken tags, no missing closing elements introduced by the restyle). All three tabs (Macro, Breadth, Execution) are navigable and display correctly after restyle.

- [ ] AC16 (density validation): If the PS spacing scale produces section gaps that impair usability for a data-heavy dashboard context, Delivery notes this explicitly in the delivery report and proposes a dashboard-adapted spacing adjustment before marking the story done.

## Notes

- **Single source of truth for visual tokens:** `PS Design.md` in `.gaai/project/contexts/artefacts/prd/PS Design.md`. All color values, typography settings, and component specs must be derived from this document. Do not introduce values not present in `PS Design.md`.
- **Font substitution:** SST (Sony proprietary) is replaced by Inter throughout. The `PS Design.md` frontmatter already declares `fontFamily: Inter` for all token roles — this is authoritative.
- **Three layers of hardcoded colors:** CSS declarations, JavaScript constants (`GRID_COLOR`, `AXIS_COLOR`, and chart series color parameters in `drawChart()`, `drawMulti()`, `drawDualAxis()`), and HTML `inline style=` attributes. All three must be updated.
- **Function names:** `drawMulti()` (not `drawMultiLine`) and `drawDualAxis()` are the chart functions requiring color constant updates.
- **Git recovery:** AC1 (git commit before edit) is the user's only non-technical recovery path if the restyle is unacceptable. Do not skip it.
