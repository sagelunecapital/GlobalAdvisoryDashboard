# Story E06S02: Implement /api/regime Live Endpoint

## User Story

**As a** fund manager,
**I want** the dashboard to fetch the current market regime live on every page load,
**so that** I always see the regime classification that reflects today's market data.

---

## Context

The regime classification requires SPX daily highs (DEC-2026-04-18-01), EMA12/EMA25, MMTH, and the divergence signal (DEC-2026-04-25-01). In the stateless API, 2 years of SPX history are downloaded from yfinance (for EMA warmup), and 2 years of MMTH history from EODData (to clear the 252-record guard in `fetch_mmth_eoddata`). Divergence is computed by calling the existing `detect_divergence()` function with `_db_rows` populated from the downloaded data — no database is opened. The report date is the last trading session date (DEC-2026-04-18-03).

If the divergence signal is DATA_GAP or unavailable, the regime is returned as unclassified (per E01S03 AC10) — no regime label or condition number is produced from incomplete inputs.

---

## Acceptance Criteria

- [ ] AC1: `GET /api/regime` downloads 2 years of SPX OHLC via `yf.download("^GSPC", period="2y")`; uses the `High` column as SPX price (DEC-2026-04-18-01 — not Close); constructs rows as `[(date_str, spx_daily_high, None)]` for downstream divergence input (MMTH column populated in AC2 merge step)
- [ ] AC2: Downloads MMTH history via `fetch_mmth_eoddata(period_days=730)` from `src/fetch/mmth.py` (730 days clears the 252-record guard); `EODDATA_API_KEY` read from environment; merges SPX and MMTH series by date to produce `_db_rows` list of `(date_str, spx_daily_high, mmth_value)` tuples covering the intersection of available dates
- [ ] AC3: Computes EMA12 and EMA25 using `ewm(span=N, adjust=False).mean()` on the full 2-year SPX High series; uses only the last row's EMA values in the response (warmup artifact is bounded to initial rows, which are discarded)
- [ ] AC4: Calls `detect_divergence(db_path=None, as_of_date=last_trading_date, _db_rows=merged_rows)` from `src/analysis/divergence.py` using the `_db_rows` injection path; `db_path=None` is passed because the function bypasses DB loading when `_db_rows` is provided; returns one of `DivergenceResult.BEARISH`, `BULLISH`, `NO_DIVERGENCE`, or `DATA_GAP`; `DATA_GAP` is returned (not raised) per DEC-2026-04-25-01
- [ ] AC5: Classifies regime using all 9 conditions from E01S03; returns regime label (`Green`, `Yellow`, `Red`) and condition number (1–9); if divergence result is `DATA_GAP`, regime classification is not computed and the response returns an unclassified state per E01S03 AC10 (see AC7 schema)
- [ ] AC6: `report_date` in response = date of the last row in the downloaded SPX series (last trading session date — DEC-2026-04-18-03); computed as `str(spx_df.index[-1].date())`, not `str(date.today())`
- [ ] AC7: Response JSON schema — normal classification: `{ "regime": "Green"|"Yellow"|"Red", "condition": 1–9, "spx_high": float, "ema12": float, "ema25": float, "mmth": float, "divergence": "BEARISH"|"BULLISH"|"NO_DIVERGENCE"|"DATA_GAP", "divergence_detail": str, "report_date": "YYYY-MM-DD", "updated_at": "<ISO-8601 UTC>" }`; unclassified state (DATA_GAP): same schema with `"regime": null, "condition": null`; `divergence_detail` is the explanation string from `detect_divergence`'s second return value
- [ ] AC8 (error-handling): yfinance fetch failure → HTTP 503 `{ "error": "spx_fetch_failed", "detail": str }`; EODData fetch failure → HTTP 503 `{ "error": "mmth_fetch_failed", "detail": str }`; EMA series produces all-NaN after dropna → HTTP 503 `{ "error": "ema_computation_failed", "detail": str }`; DATA_GAP is NOT an error — it returns HTTP 200 with `regime: null, condition: null`; no silent partial responses for fetch failures

## Out of Scope

- Regime history or trend over time
- Caching the regime result between requests
- Any database read or write (db_path=None is passed to detect_divergence; no SQLite connection opened)

## Notes

`detect_divergence` in `src/analysis/divergence.py` accepts `_db_rows=None`; when provided, the function skips the DB loading path (`_load_from_db`) and uses the injected rows directly. The tuple format expected by the function is `(date_str: str, spx_daily_high: float, mmth: float)` — matching the column names `("date", "spx_daily_high", "mmth")` in the internal DataFrame.

The 2-year download for MMTH (period_days=730) is required to clear the `len(records) < 252` guard in `fetch_mmth_eoddata`. Only the last row's values are used in the API response; the full series is needed for divergence computation.

DATA_GAP is returned when less than 90 calendar days of history is available in the merged rows (SWING_LOOKBACK_DAYS=90 per DEC-2026-04-25-01). This is not an error condition — it is a valid state (insufficient history). The API returns HTTP 200 with regime=null, condition=null.
