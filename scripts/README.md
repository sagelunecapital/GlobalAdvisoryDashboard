# `scripts/` — Dashboard data pipeline

How the Global Advisory Dashboard ([global-advisory-dashboard.vercel.app](https://global-advisory-dashboard.vercel.app),
deploys from `main`) gets its data. The UI reads JSON files in `prototypes/` directly,
plus a macro data block embedded in `prototypes/index.html`.

There are **two refresh workflows**: one automated, one manual.

---

## 1. Pipeline — `update_and_deploy.ps1` (run on `main`)

Refreshes everything **except the screener**, then **commits and pushes** the data files.
This is the daily morning routine (run it by hand; the old 8 AM scheduled task is disabled
but kept for manual launch).

```powershell
.\scripts\update_and_deploy.ps1            # full run: regenerate -> commit -> push
.\scripts\update_and_deploy.ps1 -DryRun    # regenerate + show diff, NO commit/push
```

It is **idempotent** (skips the commit when nothing changed) and **only stages an explicit
list of data files**, so any other uncommitted work (screener edits, code) is left untouched.
No `git stash` is used.

Producers it runs, in order:

| Script | Produces | Source |
|---|---|---|
| `fetch_gdpnow.py` | `prototypes/gdpnow.json` | Atlanta Fed |
| `update_dashboard.py` *(repo root)* | macro block in `index.html` | FRED / yfinance (reads `gdpnow.json`) |
| `fetch_regime.py` | `prototypes/regime.json` | FRED / investing.com |
| `barchart_fetch.py` | `barchart_zq_cache.json` (ZQ strip) | Barchart |
| `stir_pipeline.py` | `prototypes/stir.json` | ZQ cache / yfinance |
| `sector_data_collector.py` | `Sector Rotation/sector_rotation.db` + **auto-exports** `sector_rotation.json` and `ticker_perf.json` | yfinance |
| `mfra_compute.py` | MFRA attribution table in the DB | derived from DB |
| `mfra_export.py` | `prototypes/mfra_group.json` | DB |
| `cot_report_pull.py` | `data/cftc_cot.db` | CFTC |
| `export_cot_json.py` | `prototypes/cot_data.json` | DB |
| `export_price_json.py` | `prototypes/price_data.json` | yfinance OHLC |

> `export_sector_json.py` and `export_ticker_perf.py` are **not** separate pipeline steps —
> `sector_data_collector.py` imports and runs them internally after refreshing the DB.
> Keep both files; the collector depends on them.

---

## 2. Screener — manual (3 steps, NOT auto-committed)

The screener is intentionally **decoupled** from the pipeline so raw, un-enriched rows are
never auto-published.

1. **Fetch** raw movers + IPOs (TradingView):
   ```powershell
   python .\scripts\screener_fetch.py
   ```
   Writes `prototypes/screener_movers.json`, `screener_movers_cn.json`, `screener_ipos.json`.
2. **Enrich** catalysts — done directly by Claude Code (no enrichment script / API call).
3. **Commit & push** the screener files manually (separate from the data commit).

## Notes / known issues

- **Run on `main`.** The pipeline aborts on any other branch (the dashboard deploys from `main`).
- **`mfra_group.json` can lag one day** — `mfra_compute.py` sometimes reports "nothing to compute"
  even after the collector adds the latest day's rows. Pending a fix to its date cutoff.
- `barchart_zq_cache.json` is a runtime cache (untracked) regenerated by `barchart_fetch.py`.
